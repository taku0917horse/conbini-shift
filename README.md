# コンビニシフト管理

コンビニ・小規模店舗向けのシフト管理 Web アプリです。  
ブラウザだけで動作し、インストール不要でスマートフォンのホーム画面に追加できます（PWA）。

## 画面構成

画面下部に 4 つのタブがあります。

| タブ | 内容 |
|------|------|
| 📅 シフト | 曜日ごとのシフト表（バーチャート） |
| 👥 従業員 | 従業員の一覧・追加・編集 |
| ⚙️ 必要人数 | 不足リスト／募集中リスト／ルール設定 |
| 📤 共有・データ | シフト表の画像保存・JSON エクスポート／インポート |

## シフトを管理する

### シフト表の見方

- **シフトタブ**を開くと、曜日タブ（月〜日）で切り替えられるバーチャートが表示されます。
- 縦軸は時間（3:00〜翌6:00）、各バーが 1 件の勤務を表します。
- バーをタップすると勤務の編集画面が開きます。
- **赤いオーバーレイ**が表示されている時間帯は必要人数が不足しています。

### 週の切り替えとテンプレート

シフトは**週単位（月曜始まり）で日付付き**で管理します。毎週の基本パターンは**テンプレート**として別に持ちます。

- シフトタブ上部の **◀ / ▶** で前週・次週、**週の表示（例: 9/21(月)〜9/27(日)）をタップ**すると日付を指定して週を選べます。**「今週」** で今週に戻ります。
- まだ作成していない週では **「この週を作成」** が表示されます。タップするとテンプレートがコピーされ、以降の編集はその週だけに反映されます（テンプレートや他の週は変わりません）。
- 作成済みの週では **「テンプレートから作り直す」** で、その週をテンプレートの内容に戻せます（確認あり。その週の編集・当欠は消えます）。
- **「テンプレート」** ボタンでテンプレートの編集に切り替わります。テンプレートの変更は、これから作成する週にだけ反映されます。
- 不足リスト・募集中リスト・画像保存・従業員の週間スケジュールは、シフトタブで選んでいる週（またはテンプレート）が対象です。
- 以前のバージョンのデータは、起動時に自動でテンプレートとして引き継がれます。

### 当欠

週のシフトのバーをタップ → **「当欠」** をオンにして保存します。

- 当欠の勤務はグレーの取り消し線で表示され、**必要人数のカウントに含まれません**。
- その時間帯は不足リストに表示されます（行に「当欠: 名前」を表示）。
- 募集中リストにも「当欠」として表示されます。
- テンプレートには当欠はありません。

### 表示サイズの切り替え

ヘッダー右の **「コンパクト」「標準」「ゆったり」** ボタンをタップするたびに、時間軸の高さが切り替わります。

### 勤務を追加する

1. ヘッダー右の **「＋勤務追加」** をタップします。
2. 以下を設定して **「保存」** をタップします。

| 項目 | 説明 |
|------|------|
| 従業員 | プルダウンで選択 |
| 曜日 | 複数選択可。同じ内容を複数曜日にまとめて登録できます |
| 時間帯 | 帯（明朝 3–6 / 早朝 6–9 / 日勤 9–17 / 夕勤 17–22 / 夜勤 22–翌3）をタップして選びます。詳しくは[下記](#時間帯の選び方) |
| 開始時刻 / 終了時刻 | 帯を選ぶと自動で入ります。直接入力・手直しも可能。翌日にまたがる場合（例: 22:00〜翌6:00）は終了に `06:00` と入力します |
| 休憩（分） | 「なし / 45分 / 60分」ボタン、または数値で直接入力 |
| 仮（募集中）の時間範囲 | **店長関連の従業員のみ表示**。詳細は[下記](#仮募集中シフト) |

### 時間帯の選び方

- 新しい勤務の入力画面は、何も選んでいない状態で開きます。
- **つながる帯をタップすると範囲が広がります**（例: 明朝 → 早朝 で 3:00〜9:00）。夜勤 → 明朝 もつながります（22:00〜翌6:00）。
- **つながらない帯をタップすると、その帯だけの選択に切り替わります**（クリアしなくても、夕勤や夜勤を1タップで選べます）。翌6:00 を超える組み合わせや、5つ全部（24時間）になる場合も同じです。
- 範囲の端の帯をタップすると、その帯を外せます。真ん中の帯をタップすると、その帯だけの選択になります。
- 選んでいる範囲は「3:00〜9:00（6時間）」のように表示されます。時刻を手で直すと表示も追従し、帯の組み合わせと一致するときだけ帯が選ばれた状態になります。
- 「よく使う時間」の **9–13 / 13–17**（日勤の前半・後半）は、1回のタップで時刻が入ります。
- 必要人数のルールの入力画面も同じ選び方です。

### 勤務の自動結合

同じ人の勤務で、終わりと始まりがつながっているものは1つにまとめます（例: 3:00〜6:00 と 6:00〜9:00 → 3:00〜9:00）。

- 3:00 の日付の境目もつながります（例: 月 22:00〜翌3:00 と 火 3:00〜6:00 → 月 22:00〜翌6:00）。まとめた結果が翌6:00 を超える場合はまとめません。
- 当欠の有無が違うもの、仮（募集中）の範囲が2つともあってつながらないものはまとめません。仮の範囲はまとめた勤務に引き継ぎ、休憩は合計します。
- **保存したとき**: その週（テンプレート）の中でまとめます。まとめると16時間を超える場合は「◯◯さんの勤務がつながって◯時間になります。まとめますか?」と確認します（キャンセルならその結合だけ見送ります）。
- **以前のデータ**: 起動時に一度だけ、まとめられる箇所があれば案内が出ます（「書き出してからまとめる」「まとめる」「今はしない」）。
- **JSON の読み込み・クラウドからの更新**: 自動でまとめて件数を知らせます。クラウドから読み込んだ場合は、「クラウドに保存」でクラウドもまとめた形になります。

### 勤務を編集・削除する

バーをタップすると編集画面が開きます。内容を変更して **「保存」**、または **「削除」** をタップします。

## 従業員を管理する

### 従業員リストの見方

- 従業員は**区分（明朝 / 早朝 / 日勤 / 夕勤 / 夜勤）ごと**にグループ表示されます。
- タップすると週間スケジュール（各曜日の勤務時間・週合計実働）が確認できます。

### 従業員を追加・編集する

**「＋追加」** または従業員名をタップして編集画面を開きます。

| 項目 | 説明 |
|------|------|
| 名前 | シフト表・リストに表示される氏名 |
| 略称 | 印刷・画像用（2〜4 文字）。未入力の場合は名前の先頭 2 文字が使われます |
| 区分 | 主な勤務帯（明朝 / 早朝 / 日勤 / 夕勤 / 夜勤）。リストでのグループ分けに使います |
| 色 | バーの色。8 色から選択 |
| メモ | 覚え書き（シフト判定には影響しません） |
| 店長関連 | ON にすると**仮（募集中）シフト**を設定できるようになります |

### 従業員を削除すると

- テンプレートと、**今週以降**の週のシフトからその従業員の勤務が削除されます。
- **過去の週**の勤務は残り、「(削除済み)名前」と表示されます。

### 店長関連フラグを外すと

その従業員の全勤務から「仮」の設定が自動的に解除されます。

## 必要人数を設定する

**必要人数タブ → ルール設定** で、時間帯ごとに最低必要人数を設定できます。

### ルールの追加・編集

**「＋追加」** をタップして曜日・時間・人数を設定します。

| 項目 | 説明 |
|------|------|
| 曜日 | ルールを適用する曜日 |
| 時間 | 開始〜終了（帯のタップで入力。[勤務と同じ選び方](#時間帯の選び方)） |
| 必要人数 | **－ / ＋** ボタンで設定 |

- 時間帯が重複するルールがある場合は**最大値**が適用されます。
- **「全日コピー」**: 選択した曜日のルールを残り全曜日にコピーします（既存ルールは上書き）。

---

## 不足リスト

**必要人数タブ → 不足リスト** で、必要人数を満たせていない時間帯を一覧表示します。

- 時間帯フィルタで絞り込めます（明朝 3–6 / 早朝 6–9 / 日勤 9–17 / 夕勤 17–22 / 夜勤 22–翌3）。その時間帯に**重なる部分だけ**を表示します。
- 夜通しの不足は「すべて」では前日の行に「22:00〜翌6:00」のようにまとめて表示します。時間帯で絞り込むと、翌3:00以降の部分は翌日の「明朝」に表示されます。
- 行をタップすると、その時間帯で勤務追加モーダルが開きます（日時が自動入力されます）。

---

## 募集中リスト

**必要人数タブ → 募集中** で、仮（募集中）として登録されている勤務を一覧表示します。

### 仮（募集中）シフト

本来は店長が穴埋めで入る予定だが、正規のスタッフを募集中の状態を管理できます。

- **設定できるのは店長関連フラグが ON の従業員のみ**です。
- 勤務全体ではなく、**一部の時間帯だけを仮**にすることができます。  
  例: 9:00〜22:00 の勤務のうち 17:00〜22:00 だけを募集中にする。

#### シフトチャートでの表示

仮の時間範囲はバーの中に**斜線パターン**で表示されます。バー自体は 1 本のままです。

#### 募集中リストでの表示

- 仮の時間範囲（例: 17:00〜22:00）と担当者名が表示されます。
- 時間帯フィルタで絞り込めます。複数時間帯にまたがる仮シフトは、各フィルタで**その時間帯に重なる部分だけ**表示されます（不足リストと同じ基準。翌3:00以降の部分は翌日の「明朝」に表示）。

#### 人数カウントについて

仮シフトも**必要人数のカウントに含まれます**（人手は足りている扱い）。不足リストには反映されません。

## データの共有・バックアップ

**共有・データタブ**から操作できます。書き出し・読み込みはテンプレートと全週のシフトを含みます。

### 印刷（時間帯別シフト表）

**共有・データタブ → 印刷** で、**種類**（時間帯別シフト表 / ヘルプ募集一覧）・週・時間帯・向きを選んで印刷できます。下にプレビュー（実際の用紙の縮小表示）が表示されます。

| 項目 | 説明 |
|------|------|
| 開始週 | ◀ / ▶ で切り替え（シフトタブで選んでいる週と共通。テンプレート表示中はテンプレートを印刷） |
| 週数 | 1〜4週。開始週から続けて印刷します |
| 時間帯 | 開始・終了を15分単位で入力。終了が開始より前なら翌日の時刻（上限は翌6:00）。ボタン（全日 3:00〜翌3:00 / 明朝 / 早朝 / 日勤 / 夕勤 / 夜勤）で時刻を入力できます |
| 時間軸 | **縦**: 日付が列・時間が縦軸（A4 縦）／ **横**: 日付が行・時間が横軸（A4 横） |

- 1時間あたりの長さは一定（10mm）です。短い時間帯なら用紙の一部だけを使い、その分、複数の週を縦に並べて1枚に印刷します。収まらない週は次のページに送ります。
- 選んだ時間帯にかかる勤務を表示します。時間帯からはみ出す部分はバーを切り、時刻は実際の値（例: 22:00〜翌6:00）を表示します。
- 印刷は**白黒でも区別できるデザイン**です（画面のシフト表はカラーのまま）。
  - 勤務: 白地に黒枠で名前と時刻
  - 人数不足: 各日の端に太い点線枠の「不足◯」、空いている時間は網点
  - 誰もいない時間: 黒地に白抜きの「0人」、濃い網点
  - 募集中（仮対応）: 斜線
  - 当欠: 破線の枠、名前に取り消し線、黒地に白抜きの「当欠」
  - 土日の見出しは太字
- 用紙の向きは自動で設定されます。iPhone の Safari など向きが反映されないブラウザでは、印刷画面で向きを選んでください。

### 印刷（ヘルプ募集一覧）

印刷カードの **種類 → ヘルプ募集一覧** で、選んだ週の募集枠を一覧にして印刷します（A4 縦）。店内に貼り出して、入れる人に名前を書いてもらう用途です。

| 列 | 内容 |
|------|------|
| 日付 | 9/22(火) など（土日は太字）。週の区切りは二重線 |
| 時間帯 | 募集する時間（例: 17:00〜22:00） |
| 不足 | 人数と種類: 点線枠「不足」＝人数不足、黒地「0人」＝誰もいない、斜線「募集中」＝店長などが仮対応中 |
| 備考 | 当欠の人（「当欠」＋取り消し線の名前）、仮対応中の人 |
| お名前 | 手書き欄。不足人数の分だけ段があります |

- 開始週・週数（1〜4週）・時間帯は時間帯別シフト表と共通です。時間帯を指定すると、その時間にかかる部分だけを載せます。
- 不足人数や「0人」かどうかが変わるところで行を分けます。
- 行が多い場合は次のページに続きます（見出し行は各ページに付きます）。未作成の週は含まれず、欄外に注記されます。
- 白黒印刷でも区別できるデザインです。

### 画像保存

**「画像保存」** をタップすると、7 曜日分のシフト表が PNG 画像として生成されます。

- **スマートフォン**: Web 共有シート（LINE・メール等への送信）が開きます。
- **PC / 非対応ブラウザ**: 画像が新しいタブで開くので、長押し（モバイル）またはダウンロードで保存できます。

### エクスポート（書き出し）

**「書き出し」** をタップすると、従業員・シフト・ルールの全データが JSON ファイルとしてダウンロードされます。他の端末やスタッフへの共有に使えます。

### インポート（読み込み）

**「読み込み」** をタップして JSON ファイルを選択します。

- 読み込む前に**現在のデータが上書きされる**旨の確認ダイアログが表示されます（日時も表示）。
- エクスポートしたファイルのみ読み込めます（version: 2。以前の version: 1 のファイルはテンプレートとして読み込みます）。

## クラウド同期

Google アカウントでログインすると、データをクラウド（Firebase Firestore）に保存して他の端末と共有できます。ログインしなくても今まで通りこの端末だけで使えます。

**共有・データタブ → クラウド同期** から操作します。

| ボタン | 動作 |
|------|------|
| ログイン | Google アカウントでログイン |
| クラウドに保存 | この端末のデータ（従業員・テンプレート・週のシフト・必要人数）をクラウドに保存 |
| 更新 | クラウドのデータを読み込み、この端末のデータを置き換え |

- 同期は手動です（自動では反映されません）。「読み込み: ◯時◯分 ・ 保存: ◯時◯分」で、最後にクラウドから読み込んだ時刻と保存した時刻を確認できます。
- クラウドに保存していない変更があると「この端末に、クラウドへ保存していない変更があります」と表示されます。
- 最後に読み込んだ後に他の人がクラウドを更新していると「クラウドに新しい変更があります（◯◯さん ◯月◯日◯時◯分・対象）」と表示され、「更新」ボタンが目立ちます。ログインしたとき・保存した後・共有・データタブを開いたとき（1分に1回まで）に確認します。
- ログイン中に、クラウドへ保存していない変更や他の人の新しい変更があると、下の「共有・データ」に赤い点が付きます（どのタブからでも気づけるように）。
- **クラウドに保存** は、前回の同期から変更のあった部分（テンプレート／各週）だけを保存します。別の人が別の週を編集していても上書きしません。
- 同じ部分を他の人が先に保存していた場合は「◯◯さんが◯月◯日◯時◯分に更新しています。上書きしますか?」と確認されます。
- **更新** は、この端末にクラウドへ保存していない変更があるときだけ確認が出ます。

### 管理者向け: Firebase の設定

- クラウド上の保存先: `stores/main`（従業員・テンプレート・必要人数）と `stores/main/weeks/{週の月曜日付}`（各週のシフト）
- 読み書きできるのは `firestore.rules` の許可リストにあるメールアドレスだけです。メンバーを追加するときは `firestore.rules` を編集して再デプロイします。
  - Firebase CLI: `firebase deploy --only firestore:rules`
  - または Firebase コンソール → Firestore → ルール に貼り付けて「公開」

## ホーム画面への追加

このアプリは PWA（Progressive Web App）に対応しています。ブラウザからホーム画面に追加すると、アプリのように起動できます。

**iOS（Safari）**: 共有ボタン → 「ホーム画面に追加」  
**Android（Chrome）**: メニュー → 「ホーム画面に追加」

## 時刻の扱い（深夜またぎ）

このアプリは **3:00 を 1 日の起点**として扱います（例: 夜勤 22:00〜翌3:00 は同じ曜日の勤務として管理）。

- 深夜 3:00 を越える終了時刻は **「翌 HH:MM」** と表示されます。
- 勤務・ルールの入力で、翌日にまたがる場合は終了時刻に実際の時刻をそのまま入力します（例: 翌6:00 → `06:00`）。終了が開始より小さい場合、自動的に翌日として処理されます。
- 前日から続く深夜勤務は、翌曜日のシフト表にも自動的に表示されます（両日表示）。

## テスト（開発者向け）

アプリ本体はビルド不要ですが、テストの実行には [Node.js](https://nodejs.org/)（v20 以上）を使います。テストは `tests/` にあります。

### 準備（初回のみ）

```sh
cd tests
npm install
```

### 実行

| コマンド | 内容 | 必要なもの |
|------|------|------|
| `npm test` | jsdom（Node.js 上のブラウザ代わり）でアプリを動かすテスト。数秒で終わる | Node.js |
| `npm run test:browser` | 実際の Chrome で動かすテスト（Service Worker・印刷の PDF） | Chrome |
| `npm run test:all` | 上の両方 | Chrome |

- どのテストも「今日」を **2026年9月24日（木）10:00** に固定して動かします。

### 見た目の確認用の道具（テストとしては自動実行しない）

```sh
node browser/screenshots.js                      # 主要な画面を幅360pxで撮影 → tests/output/screenshots/
node browser/render-snapshot.js save before      # 今の描画を記録
node browser/render-snapshot.js save after       # （コードを変えてから）もう一度記録
node browser/render-snapshot.js compare before after   # 違う項目だけを表示
```

`render-snapshot.js` は、リファクタリングの前後で画面・リスト・印刷・画像保存の見た目が変わっていないかを確かめるためのものです。
